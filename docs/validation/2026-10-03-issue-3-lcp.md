# Issue #3: responsive hero delivery

Observed on 2026-10-03. Follow-up to [the initial rendering validation](2026-10-03-rendering-analytics.md).

The existing commit de34b10 already removes the loader and CSS/GSAP hiding of hero text, navigation, and CTAs. This change keeps that behavior and reduces image delivery costs on the home, service, and article templates. The new three-run baseline is recorded below; the changed build still requires measurement.

## Changes and local evidence

The browser PSI baseline identifies a render-blocking stylesheet and estimates 2,630ms savings on the home. Astro now inlines route CSS, and Barba retains/deduplicates inline styles on navigation. Sharp 0.34.5 is an explicit build dependency: the first Vercel preview failed to find the previously optional dependency.

`src/data/heroImages.ts` generates WebP candidates at build time from the existing public images. Each template supplies sizes matching its layout. The home preload uses the same responsive candidates as the portrait and applies only above 960px, where the portrait sits beside the text. Barba removes/replaces page-specific image preloads while preserving shared font preloads. The post-build patch rewrites every responsive candidate relative to its output HTML, including later entries in srcset/imagesrcset.

Image dimensions now come from the source metadata. The home portrait is 1086 × 1448 and the timeline article image is 1672 × 941; their previous HTML dimensions did not match the files. Existing CSS frames, object-fit, and visual composition are preserved.

| Hero | Original bytes | 400px variant | 640px variant |
| --- | ---: | ---: | ---: |
| Home | 68,804 | 11,018 | 24,620 |
| Belém | 105,626 | 14,584 | 27,866 |

These are file-size comparisons, not LCP improvements. The browser selects a candidate based on layout width and pixel density. Chrome at 390 × 844 selected the 400px variants in this environment; higher-density devices may select larger files. Full candidate sizes and paths are in [the image evidence](issue-3-image-delivery.json).

Local production-build checks:

- `pnpm run build` passes, including the post-build patch; 28 pages generated.
- `pnpm run test --maxWorkers=1` passes: 6 files, 12 tests in the isolated worktree. Earlier root-checkout counts also included a temporary duplicate checkout and are not the authoritative suite count. The sandbox initially prevented esbuild from reading parent directories; the suite passed outside the sandbox.
- All 55 responsive candidates across 28 generated HTML files resolve to existing files. Regression coverage checks root/nested HTML and both quote styles.
- Chrome at 390 × 844: home, Belém, and article H1/text remain visible; no horizontal overflow; hero images load. Home and Belém WhatsApp CTAs are visible and retain their destinations.
- Mobile menu opens; home → Belém and article → home Barba navigation work. Title/canonical update, and the home image preload is restored on return.
- Desktop home at 1440 × 900 retains its text/portrait layout. Temporary viewport overrides were reset.

Font faces already use font-display swap and critical text font preloads. No CSS hiding remains on the hero. The new PSI diagnostic supports testing CSS inlining. Font faces and preload weights are unchanged; image-size reductions alone do not establish a causal LCP improvement.
